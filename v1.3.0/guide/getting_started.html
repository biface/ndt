Part 1 — Getting Started¶

This part takes you from installation to a working NestedDictionary: building one, reading and changing it with hierarchical keys, configuring it, and choosing between the three public classes.

Installation¶

Install ndict-tools from PyPI with pip:

pip install ndict-tools

or add it to a project managed by uv:

uv add ndict-tools

The package requires Python 3.11 or later and has no runtime dependencies beyond the standard library.

Building a nested dictionary¶

Pass a plain dict to the constructor. Here is a small house of one floor: each room holds its equipment, and some equipment has settings of its own.

>>> from ndict_tools import NestedDictionary
>>> house = NestedDictionary({
...     "kitchen": {
...         "lights": "ceiling",
...         "heating": {"type": "radiator", "power": 1500},
...     },
...     "living room": {"lights": "floor lamp", "heating": {"type": "fireplace"}},
...     "garage": {},
...     "garden": {"shed": "tools"},
... })

The constructor converts every nested dict into a NestedDictionary, at every level. The garage, which has nothing in it yet, is an empty nested dictionary:

>>> type(house["kitchen"]).__name__
'NestedDictionary'
>>> type(house["kitchen"]["heating"]).__name__
'NestedDictionary'
>>> len(house["garage"])
0

to_dict() gives the content back as plain dictionaries, which is the easiest way to look at it:

>>> house.to_dict()["living room"]
{'lights': 'floor lamp', 'heating': {'type': 'fireplace'}}

The constructor accepts the same arguments as dict: an iterable of (key, value) pairs, a zip, or keyword arguments. Keyword arguments are data, never settings:

>>> rooms = NestedDictionary([("bedroom", {"lights": "ceiling"}), ("bathroom", {"lights": "mirror"})])
>>> rooms.to_dict()
{'bedroom': {'lights': 'ceiling'}, 'bathroom': {'lights': 'mirror'}}
>>> rooms = NestedDictionary(zip(["bedroom", "bathroom"], [{"lights": "ceiling"}, {"lights": "mirror"}]))
>>> rooms.to_dict()
{'bedroom': {'lights': 'ceiling'}, 'bathroom': {'lights': 'mirror'}}
>>> NestedDictionary(shed="tools", pond={"fish": 3}).to_dict()
{'shed': 'tools', 'pond': {'fish': 3}}

from_dict() builds the same structure from an existing plain dictionary. It is useful when the dictionary comes from elsewhere, for example a parsed configuration file:

>>> parsed = {"cellar": {"lights": "bulb", "boiler": {"fuel": "gas"}}}
>>> cellar = NestedDictionary.from_dict(parsed)
>>> type(cellar["cellar"]["boiler"]).__name__
'NestedDictionary'

Hierarchical keys¶

A single key works as with a plain dict, and keys can be chained:

>>> house["garden"]["shed"]
'tools'

A list of keys is a hierarchical key: it names a path from a top-level key down to a nested one, and reaches it in one step.

>>> house[["kitchen", "heating", "power"]]
1500

Writing through a hierarchical key creates the missing levels. The house gets an attic, and the kitchen a new heating power:

>>> house[["attic", "window"]] = "skylight"
>>> house["attic"].to_dict()
{'window': 'skylight'}
>>> house[["kitchen", "heating", "power"]] = 2000
>>> house[["kitchen", "heating"]].to_dict()
{'type': 'radiator', 'power': 2000}

del and pop() accept hierarchical keys too. When the deleted key was the last one of its level, the emptied levels above it are removed as well: taking the tools out of the shed removes the garden.

>>> del house[["attic", "window"]]
>>> "attic" in house
False
>>> house.pop(["garden", "shed"])
'tools'
>>> "garden" in house
False

Only del and pop() remove levels, and only the levels they empty. A level that was empty from the start, like the garage, stays:

>>> "garage" in house
True

Only a list is read as a path. A tuple is an ordinary hashable key, as in a plain dict:

>>> grid = NestedDictionary({(0, 1): "door", 0: {1: "window"}})
>>> grid[(0, 1)]
'door'
>>> grid[[0, 1]]
'window'

The in operator, get() and setdefault() take a single key, as for a plain dict. To test whether a path exists, ask the view of the paths (see Part 3 — Working with Paths):

>>> house.get("garden", "no garden")
'no garden'
>>> ["kitchen", "heating", "type"] in house.paths()
True

Configuration¶

Every nested dictionary carries a configuration, default_setup, with two settings:

  • indent: the number of spaces added at each level when the dictionary is printed;

  • default_factory: what reading a missing key does. A class creates an empty nested dictionary of that class under the key; None raises KeyError.

Without default_setup, a NestedDictionary uses indent 0 and creates NestedDictionary levels. Pass default_setup to choose; it needs both settings. Reading it returns the settings as an ordered list of pairs:

>>> kitchen = NestedDictionary(
...     {"lights": "ceiling", "heating": {"type": "radiator", "power": 1500}},
...     default_setup={"indent": 2, "default_factory": NestedDictionary},
... )
>>> kitchen.default_setup
[('indent', 2), ('default_factory', <class 'ndict_tools.core.NestedDictionary'>)]

The list is the normalized form of the configuration: always the same order, whatever the form it was given in. Printing uses indent:

>>> print(kitchen)
{
  lights : ceiling,
  heating : {
      type : radiator,
      power : 1500,
  },
}

All levels of a nested dictionary share its configuration. Assigning default_setup changes it at every level:

>>> kitchen.default_setup = {"indent": 4, "default_factory": None}
>>> kitchen["heating"].default_setup
[('indent', 4), ('default_factory', None)]

Choosing a class¶

The three public classes have the same interface. They differ in what reading a missing key does, that is, in their default_factory:

Class

Reading a missing key

NestedDictionary

Creates an empty nested dictionary under the key, like collections.defaultdict. The default_factory can be changed in default_setup.

StrictNestedDictionary

Raises KeyError. The default_factory is always None.

SmoothNestedDictionary

Creates an empty SmoothNestedDictionary under the key. The default_factory is always SmoothNestedDictionary.

With a NestedDictionary, reading a room that does not exist adds it:

>>> plan = NestedDictionary({"kitchen": {"lights": "ceiling"}})
>>> plan["office"].to_dict()
{}
>>> "office" in plan
True

This suits a house you are still furnishing. To check an inventory that is already complete, a StrictNestedDictionary reports the unknown room instead:

>>> from ndict_tools import StrictNestedDictionary
>>> inventory = StrictNestedDictionary({"kitchen": {"lights": "ceiling"}})
>>> inventory["office"]
Traceback (most recent call last):
    ...
KeyError: 'office'

StrictNestedDictionary and SmoothNestedDictionary keep their default_factory whatever default_setup says. Only indent can be chosen:

>>> from ndict_tools import SmoothNestedDictionary
>>> sketch = SmoothNestedDictionary(default_setup={"indent": 2, "default_factory": None})
>>> sketch.default_setup
[('indent', 2), ('default_factory', <class 'ndict_tools.core.SmoothNestedDictionary'>)]
>>> type(sketch["attic"]["window"]).__name__
'SmoothNestedDictionary'

Warning

Because reading a missing key adds it, a tool that reads keys it does not know changes the data. The variable viewers of debuggers built on pydevd, such as those of PyCharm and VS Code, read the attributes of a dictionary subclass as keys first: inspecting a NestedDictionary can add keys such as default_setup or _default_setup. To inspect without side effects, use a StrictNestedDictionary or set default_factory to None.

Keep in mind the difference between the attribute house.default_setup, the configuration, and the item house["default_setup"], a key of the data.
