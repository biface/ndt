Partie 5 — Étendre le paquet¶

Cette partie s’adresse aux développeurs qui écrivent leur propre classe au-dessus de ndict-tools. Elle explique de quoi hériter, comment une sous-classe définit sa configuration, et ce dont elle hérite sans rien écrire.

Classes publiques et classes privées¶

Le paquet a un moteur privé et une interface publique :

ndict_tools/
├── tools.py      ← moteur privé       (_StackedDict, _HKey, _Paths, _CPaths)
├── core.py       ← classes publiques  (NestedDictionary, PathsView, …)
├── serialize.py  ← outils privés      (encodage des clés JSON, contrôles pickle)
├── exception.py  ← exceptions
└── __init__.py   ← exporte les classes publiques et les exceptions

__init__.py exporte les classes de core.py et les exceptions, et rien de tools.py ni de serialize.py. Héritez des classes publiques, en général de NestedDictionary, jamais des classes privées : celles-ci peuvent changer d’une version à l’autre. Leur référence se trouve dans tools — Infrastructure principale et serialize — Infrastructure de sérialisation.

La configuration d’une sous-classe¶

La configuration d’un dictionnaire imbriqué, son default_setup, est ce que partagent tous les niveaux du dictionnaire : indent et default_factory pour les classes publiques. Une sous-classe étend le paquet en y ajoutant son propre réglage, qui suit alors le dictionnaire partout où va la configuration.

Toutes les façons de construire une instance résolvent la configuration par une seule méthode de classe, _normalize_setup : le constructeur, le setter de default_setup, from_dict() et from_json(). Elle reçoit le default_setup fourni par l’appelant, ou None, et renvoie la configuration à appliquer sous forme de nouveau dict, sans modifier celui qu’elle a reçu. NestedDictionary y fournit sa configuration par défaut ; StrictNestedDictionary et SmoothNestedDictionary y imposent leur default_factory.

Voici un Inventory de maison dont la configuration contient aussi l’unité dans laquelle les puissances sont exprimées :

>>> from ndict_tools import NestedDictionary
>>> class Inventory(NestedDictionary):
...     """A nested dictionary describing the equipment of a house."""
...
...     def __init__(self, *args, **kwargs):
...         self.unit: str = "W"
...         super().__init__(*args, **kwargs)
...
...     @classmethod
...     def _normalize_setup(cls, setup):
...         normalized = dict(setup) if setup else {"indent": 2, "default_factory": cls}
...         normalized.setdefault("unit", "W")
...         return super()._normalize_setup(normalized)
...
...     def total_power(self):
...         total = sum(value for path, value in self.unpacked_items() if path[-1] == "power")
...         return f"{total} {self.unit}"

Les deux méthodes ont des rôles distincts :

  • __init__ déclare unit comme attribut de l’instance, avant d’appeler le constructeur parent, comme NestedDictionary le fait pour indent. Le constructeur parent applique ensuite la configuration, et il n’accepte que des clés qui sont des attributs de l’instance : sans cette déclaration, unit lèverait une StackedAttributeError.

  • _normalize_setup donne la configuration par défaut, complète une configuration qui n’a pas de unit, et transmet le résultat à la classe parente, qui vérifie la présence de indent et de default_factory.

Quatre règles en découlent.

1. Un nouveau réglage est un attribut d’instance et une clé de configuration. Le constructeur le définit à chaque niveau, comme indent. Une maison mesurée en kilowatts :

>>> house = Inventory(
...     {
...         "kitchen": {"lights": "ceiling", "heating": {"type": "radiator", "power": 1.5}},
...         "bedroom": {"heating": {"type": "radiator", "power": 1.0}},
...     },
...     default_setup={"indent": 2, "default_factory": Inventory, "unit": "kW"},
... )
>>> house.unit, house["kitchen"].unit, house[["kitchen", "heating"]].unit
('kW', 'kW', 'kW')
>>> house.total_power()
'2.5 kW'
>>> house["bedroom"].total_power()
'1.0 kW'

Affecter default_setup plus tard modifie le réglage à tous les niveaux, comme le montre la partie 1 pour indent.

2. Définissez la valeur par défaut, ou fournissez-la toujours. Sans default_setup, un Inventory reçoit la configuration de _normalize_setup, en watts :

>>> Inventory({"office": {"heating": {"power": 500}}}).total_power()
'500 W'

Une sous-classe qui ne redéfinit pas _normalize_setup hérite de la valeur par défaut de son parent, qui n’a pas de unit.

3. Faites de la sous-classe son propre default_factory. Les dictionnaires imbriqués passés au constructeur ou à from_dict sont convertis avec la classe qui les construit. Les clés créées par la lecture d’une clé absente, en revanche, viennent de default_factory. La valeur par défaut ci-dessus utilise cls ; les deux sortes de niveaux sont donc des objets Inventory, et il en va de même pour une sous-classe de Inventory :

>>> home = Inventory({"kitchen": {"lights": "ceiling"}})
>>> type(home["kitchen"]).__name__
'Inventory'
>>> type(home["attic"]).__name__
'Inventory'

Sans cela, les deux sortes de niveaux diffèrent. Une sous-classe nue conserve le réglage default_factory de NestedDictionary :

>>> class BareInventory(NestedDictionary):
...     pass
>>> bare = BareInventory({"kitchen": {"lights": "ceiling"}})
>>> type(bare["kitchen"]).__name__
'BareInventory'
>>> type(bare["attic"]).__name__
'NestedDictionary'

SmoothNestedDictionary suit la même règle : sa méthode _normalize_setup règle default_factory sur elle-même.

4. Les autres constructeurs n’ont pas besoin d’être redéfinis. from_dict(), copy() et deepcopy() construisent avec la classe de l’instance et conservent sa configuration, unit compris :

>>> kilowatts = {"indent": 2, "default_factory": Inventory, "unit": "kW"}
>>> Inventory.from_dict({"garage": {"charger": {"power": 7.4}}}, default_setup=kilowatts).total_power()
'7.4 kW'
>>> copied = house.deepcopy()
>>> type(copied).__name__, copied.unit, copied == house
('Inventory', 'kW', True)

from_pickle() renvoie l’objet avec la configuration qu’il avait lors de son écriture. Pickle enregistre la classe par son nom ; une sous-classe enregistrée avec pickle doit donc être définie au premier niveau d’un module importable. Un fichier JSON ne contient que le contenu (voir Partie 4 — Sérialisation) : from_json() renvoie un Inventory avec la configuration par défaut, en watts, sauf si default_setup est fourni.

>>> house.to_json("house.json")
>>> Inventory.from_json("house.json").unit
'W'
>>> Inventory.from_json("house.json", default_setup=kilowatts).total_power()
'2.5 kW'

Comme unit fait partie de la configuration, il compte aussi dans les comparaisons (voir Partie 2 — Explorer un dictionnaire imbriqué) : le même contenu avec une autre unité est isomorphe, mais pas égal.

>>> watts = {"indent": 2, "default_factory": Inventory, "unit": "W"}
>>> in_watts = Inventory(house.to_dict(), default_setup=watts)
>>> in_watts == house, in_watts.isomorph(house)
(False, True)

Où le modèle est décrit¶

Le guide ne couvre que l’interface publique. La façon dont les clés d’un dictionnaire imbriqué forment une forêt, ce que sont ses chemins et ses chemins compacts, et la manière dont la couverture est calculée sont expliqués dans la section Concepts. Les classes privées qui les implémentent sont documentées dans la référence de l’API.
